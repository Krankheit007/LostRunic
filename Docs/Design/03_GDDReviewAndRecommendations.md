# GDD 评审与建议

> 评审对象：`D:/Claude/不要忘记阿黛尔.docx`
> 评审基准：原始 DOCX 与 2026-08-09 后续设计回应视为设计事实；建议、当前解释和推断单独标注。

## 1. 总体判断

文档已经建立了清晰的体验方向：儿童视角、逃难与身份追寻、四状态切换、弱势潜行、声音感知、知识锁和回忆空间。这些内容足以支撑一个首个垂直切片。

后续回应已经把输入节奏、死亡回忆流程、攻击方向、自动存档触发和道具使用路径推进到可做原型的程度。当前最大风险转为边界与数据一致性：状态输入在特殊场景如何被禁用、死亡过程中的两次存档如何保持恢复点、两种道具使用入口是否真正共享一套规则，以及阿黛尔身份和结局条件仍未锁定。

## 2. 已经清晰的部分

### 2.1 核心体验

- 潜行、解谜、叙事和知识锁的组合很明确。
- “闭眼/睁眼”是能够同时影响视觉、移动、交互和叙事的核心按钮，不是单纯的滤镜。
- 主角弱势、敌方士兵和姐姐失散构成了稳定的情绪目标。

### 2.2 规则数值

- 警戒值 0-11、不同颜色阶段、观察时间、追逐速度和衰减频率已经给出第一版可实现参数。
- 潜行、走路、奔跑速度与室内/室外声音半径已经足够制作第一版灰盒。
- 交互距离 5m、2m 和朝向 90°给出了明确的目标筛选逻辑。

### 2.3 内容方向

- 家、轮船、港口、居所和市集、农场、故乡的章节顺序清楚。
- 正常、感知、勇气、回忆四种视觉方向有初步区分。
- UI 页面清单覆盖了主界面、暂停、存档、对话、背包、笔记和收藏品。

## 3. 矛盾、风险与优先级

### 3.1 对五项回应的结论

| 原问题 | 解决程度 | 分析与后续处理 |
|---|---|---|
| 闭眼/睁眼输入语义 | **部分解决，可进入输入原型** | 键鼠/手柄映射、`0.8s` 进入阈值、`0.3s` 返回阈值、约 `1s/0.5s` 动画和中断规则已经明确。仍需确定非死亡进入回忆、勇气返回正常的最终输入、双键同时按下、每次按下只触发一次，以及对话/菜单/剧情/掩体中的输入上下文。 |
| 死亡后进入回忆 | **主体解决，需补存档边界** | “死亡次数 +1 -> 遮罩转场 -> 回忆调查 -> NPC 离场 -> 返回保存位置”已经构成完整体验闭环。技术上必须把持续进度与恢复位置分离，并保证两次关键存档顺序完成；还需决定回忆中手动存档和异常退出策略。 |
| 勇气攻击边界 | **首个切片基本解决** | 接受“只击退指定敌人、禁止击杀”，CD 暂定 `1s`，足以防止系统滑向常规战斗。尚缺资源成本、武器消耗、目标范围、敌人免疫标签和受击后的完整反制。 |
| 自动存档频率 | **方向已解决** | 改为地图切换和重要剧情事件触发，消除了每次互动写盘的问题。下一步只需建立“重要事件”标签清单，并区分普通防抖存档与死亡回忆的关键顺序存档。 |
| 快捷栏与使用交互 | **方案可行，但实现必须统一** | “快捷栏直接使用”和“默认交互后从背包选择”是合理的快慢两条路径。二者必须生成同一种物品使用请求并共享目标、条件、消耗、反馈和剧情事件结算；否则仍会产生行为分叉。 |

### 3.2 剩余风险

| 优先级 | 问题 | 风险 | 建议 |
|---|---|---|---|
| P0 | 阿黛尔身份有两个完全不同的故事方向 | 名称、线索、结局和收集品可能全部返工 | 在剧情原型前锁定“本名”或“重要他者/玩偶”，另一方案保留为否决记录 |
| P1 | 状态输入仍有特殊场景与并发边界 | 输入冲突会导致误切状态或动画卡锁 | 使用 Gameplay、Dialogue、Menu 等独立输入上下文；写完整状态/输入矩阵 |
| P1 | 死亡回忆包含两次跨地图关键存档 | 异步存档乱序会丢死亡次数、回忆事件或覆盖恢复点 | 保存独立恢复锚点；关键请求排队并做中断恢复测试 |
| P1 | 勇气武器的目标与资源规则未定 | 可能出现无成本连续控场或攻击错误目标 | 使用敌人/物品标签限定目标；确认是否消耗资源并测试 `1s` CD |
| P1 | 警戒逻辑给了很多数值但缺少边界案例 | 多敌人、跨房间、重复声源可能出现不可控行为 | 先写单敌人状态图和事件优先级，再扩展群体联动 |
| P2 | “重要剧情事件”尚无清单 | 自动存档仍可能遗漏关键进度或触发过密 | 由事件数据显式配置保存策略，不用代码按事件名称猜测 |
| P2 | 真结局只描述“足够线索” | 玩家不知道收集目标，测试也无法复现 | 使用可见的线索计数或分组条件，并为每个结局建立可验证条件 |

## 4. 必须补充（进入生产前）

1. **状态转换规范**：在现有按键与时长基础上补齐并发输入、特殊场景输入上下文、非死亡回忆入口、拒绝反馈和动画完成/中断规则。
2. **首个关卡的完整流程图**：入口、教学、第一处敌人、第一处掩体、第一次状态切换、谜题、剧情互动和出口。
3. **潜行失败协议**：死亡回忆主流程已确定；继续补齐追逐、逃脱、恢复点选择、动态敌人/交互物重置和玩家可控补救。
4. **谜题模板**：观察线索、获得知识、执行动作、验证结果、错误反馈和可选解法。
5. **阿黛尔与结局决策**：身份、姐姐线索链、真结局判定、是否允许提前发现关键事实。
6. **内容规模**：章节数量、每章目标时长、敌人种类、可交互物数量、对白字数和收集品总量。

## 5. 应当补充（垂直切片后）

- 镜头碰撞、遮挡、室内外切换和角色可见性规则。
- 音频系统：脚步、声源优先级、感知状态反馈、敌人听觉提示、对白混音。
- 动画状态：潜行、奔跑、进入/退出掩体、击退、死亡、不同年龄角色切换。
- 敌人差异：普通巡逻、固定搜查、追逐型或特殊听觉型敌人。
- 对话已经确定确认键与打字机动画跳过语义；仍需补条件、自动播放、分支回滚、文本速度设置和本地化占位。
- 无障碍：色盲辅助、字幕、震动、光敏提示、可调音量、难度/辅助模式。
- 存档兼容、旧版本迁移、损坏存档提示、回忆中异常退出和自动存档覆盖策略。

## 6. 可后置

- 地图界面。
- 更复杂的物品组合和多级快捷栏。
- 多种回忆 NPC 互动和动态提示。
- 额外叙事诡计、现实魔幻表现和非主线收集品故事。
- 主题菜单随结局变化的装饰动效。

## 7. 优势

- **差异化明确**：四状态与儿童逃难叙事的结合有辨识度。
- **低战斗依赖**：更适合小团队控制内容规模，也能保持主题一致。
- **系统能服务叙事**：感知、勇气和回忆都能直接表达心理状态。
- **线性结构可控**：家到故乡的章节顺序便于建立垂直切片和剧情测试。

## 8. 潜在缺点

- 状态过多会让操作和 UI 认知负担变高。
- 警戒数值很细，但玩家可能只感知“安全/危险”，投入与收益需要实测。
- 战争、失散、身份和精神创伤同时存在，情绪主题可能过载。
- 水彩、描边、感知显形、勇气失真和回忆场景都需要独立美术技术，早期成本不低。
- 如果知识锁缺少清晰反馈，玩家会把“没想到”误判为“游戏没做”。

## 8.1 数据调优建议

当前大量数值都应视为**首版灰盒基线**，而不是不可修改的常量。移动速度、感知半径、警戒阈值、交互距离、状态长按时间、动画安全超时、勇气攻击 CD、击退时间和自动存档防抖都应能在 UE 编辑器中的 Data Asset、DataTable、Input Action 或蓝图 Class Defaults 中调整。代码负责范围校验与规则执行，避免在函数和蓝图流程节点中散落数字字面量。

每项参数只保留一个权威来源，并记录单位、合理范围和影响系统。垂直切片盲测时应保留参数版本，防止在多个蓝图实例中分别修改后无法复现实验结果。

## 9. 建议的验证顺序

### 阶段 A：纸面规则

- 用状态表和警戒状态图覆盖全部输入与事件。
- 建立键鼠/手柄输入上下文表，并明确 Gameplay、Dialogue、Menu 和 Transition 的优先级。
- 为“家”写出 10-15 分钟的可玩流程，标注每一次玩家获得的新知识。
- 选定阿黛尔身份与真结局条件。

### 阶段 B：灰盒切片

- 只用方块、基础材质和占位 UI 验证移动、声音、视线、掩体和四状态。
- 让玩家至少有两条通过第一处敌人的路线，其中一条依赖感知线索。
- 验证 `0.8s/0.3s` 长按与约 `1s/0.5s` 动画是否既可理解又不拖慢频繁切换。
- 记录失败原因、状态切换次数、警戒停留时间和谜题卡点。

### 阶段 C：内容验证

- 加入一段对话、一份可阅读内容、一个收藏品和一次死亡回忆。
- 分别用快捷栏和背包选择同一把钥匙，确认两条路径得到完全一致的开门、消耗和存档结果。
- 在两次死亡回忆自动存档之间强制退出一次，确认读档仍返回原保存位置且保留已提交进度。
- 检查文本是否能在没有开发者解释的情况下让玩家理解规则。
- 用盲测确认“知识锁”被感知为发现，而不是不公平。

## 10. 结论

项目最值得保护的核心是“通过心理状态改变玩家对同一空间的理解”。现有回应已经让输入、死亡回忆和物品使用具备实现基础；下一步应先补齐剩余边界，并在“家”切片中验证切换节奏、关键存档事务和双路径道具使用，再扩写章节。
